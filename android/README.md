# Keel CRM for Android (Trusted Web Activity)

This is the Play Store wrapper for the Keel web app, generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) 1.25.
It adds no native code. The app opens `https://<host>/pipeline` full screen in the device's Chrome, so it uses:

- the same cookies and session as the website;
- the same CSRF handling;
- the same backend.

`twa-manifest.json` is the source of truth. Every other file here is regenerated from it.

| | |
|---|---|
| Package | `com.workeasy360.keelcrm` (permanent once uploaded to Play) |
| Host | `3-110-142-102.sslip.io` |
| Web manifest | `frontend/src/app/manifest.ts` → `/manifest.webmanifest` |
| Asset links | `frontend/public/.well-known/assetlinks.json` → `/.well-known/assetlinks.json` |

## Toolchain

You need Node 20+, JDK 17 and the Android SDK. Running `npx @bubblewrap/cli doctor` installs the last two into `~/.bubblewrap`.
On Windows, also:

- add `%USERPROFILE%\.bubblewrap\jdk\bin` to `PATH`, because Bubblewrap calls `jarsigner` from there;
- if Gradle can't download its distribution from GitHub (IPv6/NAT64 networks), set `JAVA_TOOL_OPTIONS=-Djava.net.preferIPv4Stack=true`.

## Debug APK (testing)

```sh
cd android
./gradlew assembleDebug        # → app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The debug build is signed with your machine's `~/.android/debug.keystore`. The app only opens full screen, without a URL bar, when that key's SHA-256 is in `assetlinks.json` on the live site. Get the fingerprint with:

```sh
keytool -list -v -keystore ~/.android/debug.keystore -storepass android -alias androiddebugkey
```

The file currently lists the debug key of the machine that generated this project. Remove it before a public release.

## Signed release (Play Store)

1. **Create the upload key once and keep it outside the repo.** `.gitignore` blocks `*.keystore` and `*.jks`. Back up the file and both passwords. Losing them means a key reset through Play support.
   ```sh
   keytool -genkeypair -v -keystore keel-upload.keystore -alias keel-upload -keyalg RSA -keysize 2048 -validity 10000
   ```
2. **Add the secrets to CI.** In GitHub, create the `android-release` environment with required reviewers, then add these secrets to it:
   - `ANDROID_UPLOAD_KEYSTORE_BASE64`: the output of `base64 -w0 keel-upload.keystore`;
   - `ANDROID_UPLOAD_KEYSTORE_PASSWORD`;
   - `ANDROID_UPLOAD_KEY_PASSWORD`;
   - `ANDROID_UPLOAD_KEY_ALIAS`, which is `keel-upload`.
3. **Build.** In the Actions tab, run **Android → Run workflow**. The `keel-android-release` artifact holds:
   - `keel-<version>-<code>.aab`, which you upload to Play;
   - a signed `.apk` for sideload testing.

   The run summary prints the upload key's SHA-256.

   To build locally instead, put the keystore at `android/android.keystore` and run:
   ```sh
   BUBBLEWRAP_KEYSTORE_PASSWORD=… BUBBLEWRAP_KEY_PASSWORD=… npx @bubblewrap/cli build --skipPwaValidation
   ```
   It writes `app-release-bundle.aab` and `app-release-signed.apk`.
4. **Update Digital Asset Links, then deploy the web app.** Add two fingerprints to `sha256_cert_fingerprints` in `assetlinks.json`:
   - the upload key's;
   - the Play **app signing** key's, from Play Console → Test and release → App integrity. Play re-signs the app, so without this fingerprint store installs open with a URL bar.

   You can check the live file with Google's [statement list tester](https://developers.google.com/digital-asset-links/tools/generator).

## Changing the app

Edit `twa-manifest.json`, then run `npx @bubblewrap/cli update`. This regenerates the project and bumps `appVersionCode`, which every Play upload needs.

If the site's host changes, the installed app breaks: it is bound to `host`. To avoid that:

- keep the production address stable (an Elastic IP or a real domain);
- when it does change, change `host` and every URL in `twa-manifest.json`, then run `update`, rebuild, publish a new version and deploy the site with the same `assetlinks.json`.

## Test on a device

Install the debug APK after the web change with `assetlinks.json` is deployed. Then check:

- the app opens full screen with no URL bar;
- sign-up, then the real verification email opens the app (App Links);
- sign in, kill the app and reopen it: you are still signed in;
- sign out;
- pipeline, contacts, companies, activities, products, dashboard and settings;
- attach a file to a deal;
- the system back button;
- a shared record link;
- rotation;
- a tablet.

To see link verification, run `adb shell pm get-app-links com.workeasy360.keelcrm`. It should report `verified` for the host.
