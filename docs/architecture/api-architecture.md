# API Architecture

- Base path `/api/v1/`; auth endpoints under `/auth/` (allauth headless) and `/api/v1/session/`.
- JSON only; `Content-Type` enforced; request bodies capped (default 1 MB; uploads use dedicated multipart endpoints with their own limits).
- OpenAPI 3.1 generated by `drf-spectacular`; the frontend generates TypeScript types from it in CI so client and server schemas cannot drift silently.

## 1. Conventions

| Topic | Rule |
|---|---|
| Resources | Plural nouns: `/contacts/`, `/contacts/{id}/`, `/deals/{id}/stage/` (sub-resource for stage moves), `/deals/{id}/products/` |
| IDs | UUID strings; server-generated |
| Pagination | Keyset (`?cursor=`) for grids and timelines; `limit` default 50, max 200; count endpoints separate (`/contacts/count/`) so large lists never `COUNT(*)` on every page |
| Filtering | Allowlisted fields and operators per resource (`?filter[owner]=me&filter[stage]=uuid&filter[custom.priority]=high`); unknown fields → 400 |
| Sorting | Allowlisted columns; stable tiebreak on `id` |
| Sparse fields / expansion | `?expand=company,owner` from an allowlist; no arbitrary nested expansion |
| Errors | RFC 9457 problem details: `{type, title, status, detail, errors: [{field, code, message}], request_id}`; no stack traces, no ORM messages |
| Concurrency | Mutable resources return `version`; `PATCH`/`PUT`/stage-move require `If-Match: "<version>"` (or `version` in body); mismatch → `409` with current representation |
| Idempotency | `Idempotency-Key` header supported on create endpoints and all AI action confirmations; keys stored 24 h per org |
| Bulk | `POST /contacts/bulk/` with `{ids, action, payload}`; max 500 ids; executed synchronously if < 50 else enqueued and tracked via `/jobs/{id}/` |
| Time | ISO 8601 UTC in and out; org timezone used only for rendering and for date-bucketed analytics |
| Rate limits | Per-endpoint throttles (`docs/architecture/authentication.md` §4); `429` with `Retry-After` |
| Versioning | URL major version; additive changes only within a version; deprecations announced via `Deprecation` header |
| Request id | `X-Request-ID` echoed and logged; generated by the proxy or the app |

## 2. Request lifecycle

```
proxy (TLS, size limits, basic rate limit)
 → SecurityHeadersMiddleware (CSP, nosniff, referrer, frame-ancestors)
 → RequestIDMiddleware
 → SessionMiddleware → AuthenticationMiddleware
 → CsrfViewMiddleware
 → TenantMiddleware (Actor, SET LOCAL app.current_org, session revocation check)
 → DRF view: throttle → RequirePermissions → serializer.is_valid (schema + tenant-scoped FKs)
 → service (authz.check on object, transaction, audit)
 → serializer output (explicit fields; output filtering by permission)
 → StructuredLoggingMiddleware (method, path, status, actor id, org id, duration; never bodies)
```

## 3. Security-relevant endpoint classes

| Class | Extra controls |
|---|---|
| Auth (`/auth/*`) | anonymous throttles, generic responses, CSRF, audit |
| Sensitive account actions | `reauth_required` check (10 min) |
| Exports | permission + audit + async job + signed URL + size caps + CSV formula neutralisation |
| Imports | file validation (extension, MIME sniff, size, row cap), stored under random key, processed async, per-row validation through the same serializers as the API |
| Bulk | scope pre-check, count caps, audit with affected ids |
| Admin (`/api/v1/admin/*` for members, roles, audit, settings) | Owner/Admin permission, stricter throttle, always audited |
| AI (`/api/v1/ai/*`) | per-user and per-org budgets, streaming with server-side token caps, tool audit |
| Webhooks inbound (`/hooks/{provider}/`) | signature + timestamp + replay table; no session; separate throttle; payload schema validation |

## 4. Output filtering

Serializers never serialise `password`, secrets, internal flags, or another tenant's data. Responses include `owner` as `{id, display_name}` only. Audit entries returned to admins redact `metadata` keys on a denylist (`token`, `secret`, `password`, `authorization`).
